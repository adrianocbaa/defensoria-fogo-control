# Avaliações — shared modules

- Criterion 1 relationship charts come from the pure `relacionamento.ts` over the stored execution coefficients and `regression_input` (vary one variable within its observed range, others at their original-scale mean, inverse of the dependent transform); the evaluator's visual analysis is recorded only through `aval_relationship_visual_review` in `audit_events`, and becomes a manual review only when the policy rule is not AUTOMATICO. Why: diagnostics never refit the model nor invent normative obligations.
- Criterion 12 (Outliers) is classified by `classifyOutliers` from the policy's OUTLIERS thresholds (decision metric named explicitly, other diagnostics shown as complementary; empty thresholds keep the legacy always-review behavior); it never fails a model, and per-sample evaluator decisions go only through `aval_outlier_decision` into `audit_events`, with exclusion creating a derived model via the existing model creation flow. Why: suspicious points may be legitimate market data and the validated model must never change silently.
- Economic result × administrative values are compared only in the same unit: `aval_confirm_economic` classifies the dependent variable by metadata (`aval_unidade_classificar`: unit, source field, assessment purpose/periodicity), converts totals to R$/m² by the appraised property's built area (projection snapshot first, then the property record) via the pure `aval_compat_calcular`, and stores original value/unit, converted value/unit, area, formula and status; missing area or incompatible units store "não comparável" with no percentage. Front-end and laudo (`compatView`) only display stored fields; legacy rows (`regra_versao` NULL) stay untouched and dimensionally wrong current results are made DESATUALIZADO by `aval_compat_revisar_legado`. Why: R$/m² was compared directly with R$/mês (−16.878%) and history must never be rewritten.
- Avaliações DIF report: layout `DIF_V1` laudos are composed only from the single `aval_laudo_snapshot_build` snapshot by pure `laudoDif.ts` into one block model rendered by `laudoDifRender.ts` to both DOCX and PDF (browser draft and server issue); images come from `laudo_midias` (org/avaliação path, SHA-256 checked at issue) and charts from pure `chartPng.ts`; legacy layouts keep `laudoDoc.ts`. Why: DOCX/PDF never diverge and emitted files stay reproducible from the frozen snapshot.
